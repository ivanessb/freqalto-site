LAME 3.100 (libmp3lame) – LGPL v2 or later

ToneGenPro uses the LAME MP3 encoder (version 3.100) for MP3 export. It ships as a separate shared library, libmp3lame.so (lib/<abi>/libmp3lame.so inside the app package), loaded at run time by ToneGenPro's native audio library through LAME's standard public C API (lame_init, lame_encode_buffer, lame_encode_flush, lame_close, get_lame_version), so it can be replaced by a modified build.

Corresponding source (exactly what ToneGenPro builds)

  • lgpl/source – the LAME 3.100 sources used by ToneGenPro, the build files (Android.mk, Application.mk) and the license texts (lame/COPYING, lame/LICENSE).
  • Differences from the LAME 3.100 release: the decoder (HIP) is replaced by lame/hip_stub.c (encoder only), and Android build configuration is provided by lame/config.h, lame/lame_config.h and lame/vector/lame_intrin.h. The encoder sources themselves are those of LAME 3.100.
  • Upstream: LAME 3.100 download.

How to replace libmp3lame.so with your own build (Android)

  1. Download the sources from lgpl/source (this repository) and edit LAME as you wish.
  2. Build with the Android NDK (r28 or newer): 
    ndk-build NDK_PROJECT_PATH=. APP_BUILD_SCRIPT=jni/Android.mk NDK_APPLICATION_MK=jni/Application.mk
    The result is libs/arm64-v8a/libmp3lame.so and libs/x86_64/libmp3lame.so. Keep the -Wl,-z,max-page-size=16384 link flag (16 KB page size, required on current Android versions).
  3. Unpack the app package (apktool d on an APK, or extract the split APK from a device with adb), replace lib/<abi>/libmp3lame.so with your build, then rebuild, zipalign -P 16 and sign it with your own key (apksigner) and install it. Because the package will carry your signature, it installs as a separate/updated app from your own signing identity, not as the Google Play version.
